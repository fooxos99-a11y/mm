# كيف نتعامل مع البيانات والخصوصية؟

هذي القواعد تمشي على بيانات الموقع والنسخ الاحتياطية. مسؤول النظام هو اللي يتابعها، والأفضل يراجعها كل ستة شهور أو بعد أي تغيير كبير بالمشروع.

## مين يشوف وش؟

- كلمات المرور تعتبر حساسة جدًا، وتنحفظ hash بس. لا تطلعها بالـAPI ولا بالسجلات ولا بأي تصدير.
- رموز الدخول والأسماء والإيميلات والنتائج والحضور تعتبر بيانات شخصية، وما يشوفها إلا الشخص اللي عنده صلاحية وعلى نفس الفرع.
- سجل النشاط ممكن يحتوي رقم مستخدم أو عملية سواها، بس لا تحط فيه كلمات مرور أو cookies أو API tokens.
- النسخ الاحتياطية تعاملها مثل قاعدة الإنتاج: تشفير وقت النقل والتخزين، وما توصل لها إلا الناس المسؤولين عن الاستعادة.

## كم نخلي البيانات؟

| نوع البيانات | كم نخليها؟ | وش نسوي بعدها؟ |
|---|---:|---|
| حسابات وبيانات البرنامج الشغال | مدة المشاركة + 12 شهر | نحذفها أو نخفي هوية صاحبها بعد موافقة المسؤول |
| طلبات التسجيل المرفوضة أو الملغاة | 90 يوم | تنحذف نهائي |
| سجلات النشاط والأمان | 12 شهر | تنحذف بشكل دوري إلا لو فيه تحقيق شغال |
| الأرشيفات التعليمية | 24 شهر | تنحذف بعد مراجعة المسؤول والتأكد إنه ما فيه التزام يمنع الحذف |
| النسخ الاحتياطية | 30 يوم | تتدوّر وتنحذف آليًا بشكل آمن |
| الجلسات والرموز | على حسب انتهاء الجلسة، وبحد أقصى 30 يوم للخامل | تنلغي وتنحذف |

لو فيه عقد أو نظام يطلب مدة أطول، وقف الحذف للبيانات المطلوبة بس، وسجّل السبب ومين وافق ومتى تنراجع مرة ثانية.

## إذا أحد طلب حذف بياناته

1. تأكد من هويته ومن وش البيانات اللي يقصدها.
2. خذ موافقة مسؤول البيانات قبل حذف أي سجلات تعليمية مرتبطة بأشياء ثانية.
3. جرّب الحذف على staging أول، ولا تشغّل SQL على الإنتاج إلا بتصريح واضح.
4. سجّل إن العملية صارت، بس لا تنسخ البيانات الشخصية المحذوفة داخل السجل.
5. البيانات تختفي من النسخ الاحتياطية بعد ما تخلص دورة الـ30 يوم، ولا ترجعها إلا باستعادة كارثية موثقة.

## وش نراجع بشكل دوري؟

- شغّل `npm run check:secrets` عشان ما تدخل مفاتيح أو ملفات بيئة بالغلط.
- تأكد إن اختبارات الدخول والصلاحيات وعزل الفروع شغالة.
- راجع صلاحيات الإنتاج والنسخ الاحتياطية كل ثلاثة شهور.
