# الإدارات داخل الموقع

الموقع وصفحة الدخول وقاعدة البيانات واحدة. كل حساب تشغيلي يتبع إدارة واحدة، بينما المدير العام يدير الإدارات ويصل إلى الأرشيف المركزي. أرقام الدخول فريدة على مستوى النظام وتظل محجوزة بعد الحذف والأرشفة.

## الأدوار

- `super_admin`: المدير العام. يدخل `/management` وينشئ إدارة ويعيّن مسؤولها بحساب مسجّل.
- `admin`: مسؤول الإدارة. مسماه الظاهر يأتي من `departments.manager_title`؛ له صلاحيات الإدارة داخل إدارته فقط.
- `male_manager` و`female_manager`: صلاحيات القسم داخل الإدارة.
- حسابات المعلمين والمقرئين والمتدربين تتبع الإدارة التي أنشأتها.
- `unassigned`: حساب مسجّل عبر `/register-account` ينتظر تعيينه. لا يصل إلى البيانات التشغيلية.

المدير العام يفتح إدارة من لوحته ليتعامل مع وظائفها، ويعود عبر «إدارة النظام». لا يصبح الحساب مديرًا عامًا من التسجيل العام أو من لوحة مسؤول الإدارة.

## الترحيل والتشغيل المحلي

1. خذ نسخة احتياطية متسقة من قاعدة البيانات والملفات قبل تطبيق الترحيل على بيانات قائمة.
2. شغّل `node scripts/run-php.mjs backend/artisan migrate` على قاعدة **محلية** بعد التحقق من إعداداتها. الترحيل يضيف الإدارة الحالية ويربط بها البيانات القديمة، ويحوّل مفاتيح الإعدادات إلى مفاتيح مستقلة لكل إدارة.
3. ينشئ المسؤول الجديد حسابه من `/register-account` ويحصل على رقم دخول فريد.
4. لتعيين أول مدير عام، استخدم حسابًا معلومًا ومصرّحًا به:

   ```powershell
   node scripts/run-php.mjs backend/artisan departments:assign-general-manager <LOGIN_CODE>
   ```

   الأمر يرقّي حسابًا موجودًا ومتاحًا ويُنهي جلساته السابقة، ولا ينشئ كلمة مرور أو حسابًا افتراضيًا. إذا كان الحساب مسؤولًا معيّنًا لإدارة، يلزم استبداله أولًا.

5. يسجّل المدير العام الدخول ويضيف الإدارة باسمها، ومسمى مسؤولها ورقم حسابه. الحساب يجب أن يكون غير مرتبط بإدارة أخرى. تبقى الحسابات القديمة ضمن الإدارة الحالية ببيانات دخولها السابقة.
6. يضيف مسؤول الإدارة المستخدمين؛ تُستنتج الإدارة من جلسته. الدورات والاختبارات والتسجيل والإشعارات والنتائج والإعدادات والأرشفة مستقلة.

إذا وجدت مرفقات تدريب قديمة على القرص العام، افحصها ثم انقلها إلى التخزين الخاص قبل اعتماد العزل:

```powershell
node scripts/run-php.mjs backend/artisan department:secure-legacy-media
node scripts/run-php.mjs backend/artisan department:secure-legacy-media --apply
```

الأمر الأول يعرض العدد فقط. الثاني ينسخ الملفات ويتحقق من SHA256، ثم يغيّر السجلات ويحذف النسخة العامة المطابقة بعد نجاح النقل. يحتفظ بالأصول عند فشل التحقق، ويُرجع فشلًا إذا بقي تنظيف مطلوب. صور الصفحات العامة لا تدخل في هذا النقل. خذ نسخة احتياطية، وتحقق من اكتمال النقل قبل التشغيل الفعلي؛ ترك المرفقات القديمة في التخزين العام يسمح بروابطها السابقة بتجاوز صفحة الصلاحيات.

لا تنفّذ هذه الأوامر على الإنتاج دون طلب نشر صريح ونسخة احتياطية وخطة رجوع.

## حدود العزل

`ResolveDepartmentContext` يحدّد الإدارة من الحساب، ويمنع حسابًا عاديًا من تبديلها. المدير العام يختار سياقه صراحة عبر `management/context`؛ تحفظ جلسة المتصفح السياق، ويحمل عميل API أيضًا `X-Department-Id`.

جميع استعلامات بيانات التطبيق تستخدم `DepartmentData` ونماذج البيانات تستخدم `BelongsToDepartment`. القراءة والتعديل والحذف والوصلات والاستعلامات الفرعية مقيّدة بالإدارة، والإدراج يضيفها تلقائيًا. يظل `users` عالميًا للمصادقة والتحقق من تفرّد رقم الدخول؛ استعلامات إدارته التشغيلية مقيّدة صراحة.

يحظر السياق الخالي الوصول إلى بيانات الإدارات. التجميع والأرشيف المركزي يمران بمسارات مخصصة للمدير العام. لا تستخدم `DB` العالمي في خدمة تشغيلية جديدة؛ يستخدم فقط للمصادقة والمخطط والعمليات المركزية المقصودة.

مرفقات الإجابات لها روابط موقّعة تتطلب المصادقة وتتحقق من ملكية الإدارة والنتيجة. مرفقات التدريب الجديدة تخزّن في القرص الخاص، وتُقرأ من مسار مصرح. صور محتوى الصفحات العامة تبقى محتوى عامًا.

## الأرشفة وأرقام الدخول

الأرشفة تحفظ الإدارة الأصلية والسجلات التاريخية وتعمل داخل نطاقها. `reserved_login_codes` يحفظ الأرقام القديمة حتى عندما يحذف التدفق القديم حساب الطالب المؤرشف. لا تعِد استخدام رقم محجوز لشخص جديد.

المخطط القديم لا يحتفظ بتاريخ أرقام جميع الحسابات المحذوفة قبل هذا الترحيل؛ تُحجز الأرقام التي ما زالت موجودة في الحسابات وسجلات الطلاب والأرشيف، ثم كل رقم جديد أو معدّل مستقبلًا.

## الرجوع

الترحيل يرفض الرجوع إذا وجدت إدارات إضافية، لأن دمج إعداداتها في مفاتيح النظام القديم سيُفقد البيانات. بعد الاستخدام الفعلي يكون الرجوع باستعادة نسخة متسقة من قاعدة البيانات والملفات والكود، أو بإصلاح أمامي. تبديل الكود القديم وحده لا يكفي بعد تغيير المخطط.

## التحقق

اختبارات العزل تشمل الحسابات، وتغيير السياق، والصلاحيات، والتسجيل، وتشغيل الدورات، وأرشفة إدارة دون التأثير على أخرى، وحجز الأرقام، والاستعلامات المركبة. اختبارات المتصفح تشمل لوحة المدير العام والتسجيل والانتقال بين لوحتي النظام والإدارة على الجوال والكمبيوتر.

يمكن تشغيل الاختبارات المعزولة أولًا:

```powershell
node scripts/run-php.mjs backend/artisan test --filter=Department
npm --prefix frontend run test:unit
npm --prefix frontend run test:e2e:dist -- departments.spec.mjs departments-live.spec.mjs --project=mobile-390 --project=desktop-1440
```

اختبارات المتصفح تنشئ قاعدة SQLite وملفات مؤقتة وتستخدم حسابات اختبار فقط. فحص MySQL يجب أن يستخدم قاعدة مؤقتة مستقلة، ولا يُعد دليلًا على ترحيل الإنتاج.
