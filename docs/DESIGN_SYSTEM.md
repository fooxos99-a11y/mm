# نظام تصميم ممارس

هذه المرحلة تطوّر طبقة الواجهة المشتركة الحالية في `frontend/src/components/ui` وملفات `frontend/src/styles/ui-*.css`. لا تضيف مكتبة مستقلة ولا تغيّر منطق الأعمال أو API أو البيانات.

## القيم الأساسية

المصدر المركزي لمتغيرات CSS هو `frontend/src/styles/main.css`. وتطابق ألوان Vuetify في `frontend/src/plugins/vuetify.js` هذه القيم.

| الاستخدام | القيمة |
| --- | --- |
| أساسي | `#1D6A85` |
| غامق ونص أساسي | `#17394B` |
| خلفية | `#F5F8FA` |
| سطح البطاقات والحقول | `#FFFFFF` |
| حدود | `#DDE5EB` |
| نجاح | `#16805D` |
| خطأ | `#D14343` |
| نص ثانوي | `#526777` |

الخط المعتمد هو Tajawal المثبت والمحمّل محليًا بالمشروع؛ IBM Plex Sans Arabic غير موجود ضمن الاعتماديات الحالية. لا توجد إضافة اعتماد أو تحميل خط خارجي.

- المسافات: `--app-space-1/2/3/4/5/6/8` تمثل 4، 8، 12، 16، 20، 24، 32px.
- الحقول والأزرار: ارتفاع أساسي 48px؛ أزرار الأيقونات الصغيرة وترقيم الصفحات 44px كحد أدنى للمس.
- الزوايا: 8px للحقول والأزرار، و12px للبطاقات والنوافذ.
- النص: 16px للحقول والأزرار، و14px للتسميات والنصوص المساعدة، و18px لعناوين المكونات المشتركة.
- حشو البطاقة: 16px للجوال، و24px لبطاقات مساحة الإدارة بدءًا من 768px.
- الظل: خفيف للبطاقة، وأوضح للقائمة أو النافذة المنبثقة فقط.

## قواعد الاستخدام

- استورد الأزرار والحقول والقوائم والبطاقات والنوافذ من المكونات الحالية. ملفات إعادة التصدير القديمة تظل متوافقة.
- استخدم `AppTextField` و`AppPasswordField` و`AppSelect` لحقول Vuetify، و`AppInput` و`AppNativeSelect` للحقول الأصلية.
- استخدم `AppFilterField` و`AppFilterToolbar` للفلاتر؛ تخطيط الجوال يبدأ بعمود واحد ثم يتوسع حسب العرض وعدد الحقول.
- احتفظ بالتسميات ورسائل الخطأ. `AppInput` يربط الرسالة بالحقل عبر `aria-describedby` ويعلن الخطأ بـ`aria-invalid`.
- يظهر التركيز بلوحة المفاتيح بحد أو حلقة واضحة. تبقى حالات التحميل والتعطيل ومنع النقر المعتمدة في المكونات.
- استخدم الخصائص المنطقية مثل `padding-inline` لدعم RTL، واسمح بالتفاف النصوص الطويلة. الجداول تتحول إلى بطاقات في المقاسات الصغيرة.
- استعمل المتغيرات المركزية بدل تكرار ألوان أو ظلال أو ارتفاعات جديدة في الصفحات.

## حدود المرحلة

توحيد المكونات الأساسية والبطاقات والفلاتر المشتركة. تبقى تركيبات الصفحات الخاصة مثل الواجهات التسويقية ومحررات الأسئلة ضمن تصميمها الحالي؛ لا تعني هذه المرحلة إعادة تصميم كل صفحة.

## التحقق

تشمل الفحوص البناء وLint والاختبارات الحالية، ومصفوفة المتصفح 320، 390، 768، 1024، 1440px. يضيف `frontend/e2e/design-system.spec.mjs` تحققًا من التركيز بلوحة المفاتيح، وإظهار كلمة المرور وإخفائها، واحتواء القائمة والحقول، وقياسات المكونات المشتركة الفعلية.

صور المقارنة المحلية وسجلات الفحص محفوظة في `.deploy/design-system/`، ولا تدخل ضمن المصدر أو النشر.

## المرحلة الثانية: مساحة الاختبارات والتحضير

- `AssessmentIndicators`: دائرتا متوسط الدرجة للقبلي والبعدي باستخدام `AppIndicatorRing` المشترك مع الرئيسية، وبينهما فرق النسب وفق الحساب الموجود. اللون الأخضر للفرق الموجب والأحمر للسالب، والمقارنة الناقصة تعرض شرطة. الدرجة الكلية متاحة ضمن اسم الوصول.
- `AssessmentAttendanceList`: اسم المعلّم وحالة التحضير فقط، دون رقم دخول أو بحث أو عداد أو زر حفظ دائم. الحالة المحددة تستخدم اللون الأساسي. الحفظ تلقائي والتحديث في الخلفية دون إخفاء الصفحة، وتظهر رسالة الخطأ وإعادة المحاولة عند الفشل فقط. التحديد العام يشمل الفرع كاملًا. ينتظر تغيير الفرع أو الدورة أو مغادرة الصفحة الحفظ المعلّق؛ إذا تعذر الحفظ، يمكن البقاء لإعادة المحاولة أو الموافقة على المغادرة دون حفظ. يبقى هيدر التحضير ظاهرًا وفارغًا، مع زر القائمة على الجوال.
- `AssessmentEditorQuestion`: بطاقة مشتركة للسؤال، ونصوص تتمدد بحسب المحتوى والعرض، ونوع السؤال ودرجته وخياراته والإجابة الصحيحة. يحافظ محررا الأسئلة الجديدة والمحفوظة على المعالجات الحالية، ويستفيد محرر الاختبار النهائي من البطاقة المشتركة نفسها.
- مساحة المحرر تبدأ بالفلاتر، دون عنوان مرئي أو ملخص درجات أو زر معاينة أو تنبيه دائم بالتعديلات. يحتفظ `AssessmentEditorHeader` بالتنقل بين الأسئلة، و`AssessmentEditorDialogs` بتأكيد المغادرة. كل خيار إجابة حقل واحد بجانبه زر صح؛ المحدد يستخدم اللون الأساسي. زر بدء الاختبار أو إدارته في الهيدر يستخدم إجراء الفتح الموجود وصلاحياته ومدته وفروعه، بينما يبقى الحفظ داخل المحرر.
- قائمة الدورات والمهام تعرض كل اسم مرة واحدة، وبجانبه أيقونات الإجراءات المدعومة. يعيد `AppSelect` استخدام قائمة Vuetify، مع صفوف `grid` عند وجود إجراءات، وأسماء وصول ومناطق لمس 44px وأيقونات 18px بلا خلفية، والحذف باللون الأحمر وتنقل بلوحة المفاتيح. تبقى القوائم العادية كما هي. وصف المهمة بعرض كامل وارتفاع أدنى 120px، والرابط تحته.
- أزرار أدوات محرر وورد لا تقل عن 44px، وتتكيف شبكة الأدوات مع العرض الصغير؛ تبقى وظائف التنسيق والحفظ نفسها.
- رمز التحميل مشترك بين التحميل الأولي والتنقل ومكونات التحميل، من `loading-indicator.css`. الحالة لها اسم وصول دون نص مرئي، وتحترم تفضيل تقليل الحركة.
- قوائم نافذتي البدء والإدارة ترتبط بتسميات الحقول لقارئات الشاشة. يبدأ التركيز في نافذة الفتح على عنوانها بدل حقل الفرع. يغلق Escape القائمة المفتوحة أولًا، ثم النافذة عند الضغط مجددًا، دون تغيير البيانات أو قواعد الإتاحة.
- تغيير الدورة أو النوع أو مغادرة المحرر يطلب تأكيدًا داخل الواجهة عند وجود مسودة. يحذر المتصفح عند إعادة التحميل أو إغلاق الصفحة، وتبقى المسودة عند إلغاء المغادرة. تحديث الكتالوج يثبت الدورة المختارة ولا يستبدل السؤال الجاري تحريره؛ تبقى الروابط الجديدة الصريحة قابلة لتغيير الدورة.
- تُعطّل الفلاتر مؤقتًا أثناء انتظار تغيير السياق، ولا يستبدل الانتقاء المتأخر انتقاءً أحدث للدورة أو النوع أو الفرع.

لا تتغير حسابات الدرجات أو التصحيح أو عقود API أو مخطط البيانات. صور هذه المرحلة وسجلاتها المحلية في `.deploy/phase2/`.

## النوافذ والاختيار المباشر

- نوافذ الإدارة تستخدم رأسًا واحدًا وحشوًا مشتركًا، مع إجراءات متجاورة ما دام العرض يسمح. المحتوى الطويل قابل للتمرير.
- ربط المقرئ أو المقرئة: مربعات أسماء دون بحث أو رقم دخول، مع صفحات للأسماء الكثيرة. الضغط يربط تلقائيًا، والضغط على الاسم المحدد يفك الربط وفق الصلاحية الحالية. يبقى الاسم المحدد متاحًا عند تغيير الصفحة؛ فشل الحفظ يستعيد الاختيار السابق ويعرض خطأ.
- استبيان الرضا: قائمة واحدة تضم جميع الدورات وأسماء الدورات الفعلية، ومفتاح إلزامي باللون الأساسي المعتم. يبقى نطاق الحفظ العام أو الخاص بالدورة مطابقًا للعقد الحالي.
