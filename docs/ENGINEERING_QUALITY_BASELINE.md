# كيف نفحص جودة المشروع؟

أي تعديل لا تعتبره جاهز إلا بعد ما تنجح الفحوصات اللي تخصه. لا تعتمد على كلام يدوي أو درجة محفوظة قديمة.

## الفحص السريع

```bash
npm run verify:quick
```

هذا يفحص الأسرار، وأحجام الملفات، وسياسة الحزم، وlint، واختبارات الواجهة.

## الفحص الكامل

```bash
npm run verify:full
```

هذا يزيد عليها اختبارات الـbackend، وبناء الإنتاج، وحدود حجم الحزم، واختبارات المتصفح.

## فحص النسخة قبل التشغيل

```bash
npm run verify:release
```

هذا يشغّل الفحص الكامل واختبارات التشغيل وقياس أداء الجوال. هذا الفحص يتطلب مستودع Git نظيفًا؛ يفشل إذا كان مجلد المشروع نسخة ملفات بلا Git.

## أشياء ما نتساهل فيها

- ترقيات Vue 3 وVuetify 3 تحتاج فحص البناء ورحلات المتصفح.
- لا تضيف ملفات أكبر من الحدود الموجودة في `.quality/code-size-baseline.json` بدون سبب واضح.
- أي ثغرة عالية أو حرجة لازم تنحل، أو يكون لها استثناء مؤقت بتاريخ انتهاء.
- اختبارات الدخول والصلاحيات والفروع لازم تنجح قبل الدمج.
- build واختبارات المتصفح وحدود الحزم لازم تنجح في CI.
- إذا غيرت سلوك بالنظام، حدّث اختباره وشرحه معه.

## نطاق التغطية

`test:coverage` يقيس وحدات المنطق المحددة في `frontend/package.json`، وليس كل ملفات الواجهة.
حدوده: 90% للأسطر، و80% للفروع، و100% للدوال. اختبارات Vue والمتصفح مكملة لهذه النسبة؛ لا يجوز عرضها كتغطية كاملة للمشروع.

## قواعد الحضور والحسابات

- `ManualAttendanceService` مسؤول عن حفظ الحضور؛ نطاق المشرف مشتق من حسابه على الخادم.
- شاشتا الحضور ترسلان الفرع المختار. قائمة فارغة تعني إلغاء حضور هذا الفرع.
- مسار المدير القديم دون فرع يستبدل حضور الدورة لجميع الفروع؛ لا تستخدمه في شاشة تعرض فرعًا واحدًا.
- قواعد كلمات المرور الجديدة مركزية في `PasswordPolicy`، وتطابقها `passwordPolicy.mjs` في الواجهة.
- الحسابات الموجودة تحتفظ ببيانات دخولها؛ السياسة تنطبق عند إنشاء كلمة مرور أو تغييرها.

## اكتمال النتائج وحدود التوسع

يقبل مسارا snapshot العام ولوحة التحكم `page`، وتحدد `snapshotMeta.*.nextPage` وجود نتائج تالية.
تجمع `completeSnapshot.mjs` صفحات النتائج قبل نشرها في المخزن. إذا فشل تحميل صفحة يُرفض التحميل، فلا تُعرض مجاميع جزئية على أنها كاملة.
أزيل القطع الصامت للطلاب والأسئلة والبيانات المرجعية، مع استمرار تقييد البيانات بالدور والفرع.

هذه معالجة لاكتمال البيانات وليست تحويلًا كاملًا للواجهة إلى تحميل عند الطلب: قوائم الطلاب والأسئلة تبقى محملة كاملة، والنتائج تتجمع في ذاكرة المتصفح.
الانتقال إلى أحجام كبيرة يتطلب بحثًا وتصفحًا مستقلين لكل شاشة، ومجاميع محسوبة من الخادم، واختبار حمل على MySQL.
الصفحات مرتبة بتاريخ ومعرّف ثابتين، لكنها لا تمثل لقطة معزولة زمنيًا إذا تغيرت البيانات أثناء التنقل؛ يجب الانتقال إلى cursors أو إصدار snapshot عند اشتراط هذا الضمان.

## دليل المعلمين والمقرئين

`GET /api/dashboard/people` يبحث بالاسم أو رقم الدخول (`search`)، ويقبل `branchCode` و`type` و`sort` و`page` و`perPage`.
الواجهة تعرض 20 بطاقة في الصفحة. الحد الأعلى للطلب 100، ونطاق المشرف يُتحقق منه على الخادم حتى عند تزوير الفرع في الرابط.
تحسب `PeopleDirectoryService` الأجزاء والحضور والاختبارات والمهام المعتمدة من كامل البيانات النشطة، ثم ترتب وتقسم النتائج.
لذلك يعكس ترتيب الإنجاز كل النتائج، ولا يعتمد على الصفحة المعروضة. تُلغى طلبات البحث القديمة عند تغيير النص أو الفلاتر.

الرئيسية ودليل المستخدمين يبدآن الآن بـ `GET /api/dashboard/shell`: صلاحيات المستخدم وفروعه والمؤشرات المسموح بها فقط.
تحسب `DashboardOverviewService` مجاميع البرنامج باستعلامات تجميع، دون إرسال سجلات الطلاب والإجابات. اختبار 1001 معلم يتحقق من احتساب الجميع وبقاء الاستجابة أقل من 6000 بايت.
يحتسب مؤشر المهام في الرئيسية التسليمات المؤهلة، بينما إنجاز بطاقة المعلم يحتسب المهام المعتمدة؛ هذا يحافظ على تعريف المؤشرين السابق.

الأقسام القديمة تطلب snapshot الكامل قبل عرضها. نوافذ المستخدمين أصبحت مستقلة عنه:

- `GET /api/dashboard/people/options` يبحث ويقسم خيارات المعلمين والمقرئين، دون مؤشرات أو ملفات تسجيل.
- `GET /api/dashboard/people/{type}/{id}` يحمل سجل الشخص المحدد والأجزاء ومعرّفات العلاقات اللازمة للتحرير. الوصول مقيد بصلاحية المستخدمين والفرع والسجلات النشطة.
- `PeopleRemotePicker.vue` مكون مشترك للبحث واختيار هدف التحرير والإدارة والمقرئ والمعلمين المرتبطين، مع إلغاء الطلبات القديمة وأزرار لمس 44px.
- معرّفات المعلمين المختارين تبقى مستقلة عن صفحة الخيارات، لمنع فقدان الروابط عند الانتقال أو البحث. تفاصيل المقرئ تحمل معرّفات روابطه القائمة كاملة للحفاظ عليها عند الحفظ.
- تحديث المستخدمين والاستيراد والأجزاء يحافظ على نوع snapshot الموجود: الرئيسي الخفيف يبقى خفيفًا، واللقطة الكاملة المفتوحة سابقًا تُحدّث لتجنب عرض بيانات قديمة في أقسامها.

فشل تحميل التفاصيل يمنع فتح نموذج ناقص ويتيح المحاولة مجددًا. طلبات المخزن تحمي من نشر استجابة قديمة بعد طلب أحدث أو تغيير الحساب.
البيانات الكاملة تبقى في الذاكرة بعد فتح قسم قديم يحتاجها؛ النتائج القديمة لم تتحول كلها إلى تصفح خادمي مستقل بعد.
لا توجد تغييرات مخطط قاعدة بيانات أو أوامر SQL إضافية لهذه المرحلة.

## النتائج المستقلة

شاشة النتائج تبدأ بالهيكل الخفيف وكتالوج الأقسام، ثم تجلب 20 معلمًا من `GET /api/dashboard/results` مع أسئلة القسم المختار وإجابات الصفحة فقط. البحث وحالات الحضور والغياب تطبق قبل تقسيم الصفحات؛ إجمالي الحضور والغياب يحسب لكامل الفرع. تحفظ صلاحيات مفاتيح الإجابات والتصحيح، وتلغى الاستجابات القديمة عند تغيير الفلاتر. تبقى شاشة التحضير القديمة وبعض الأقسام الأخرى بحاجة إلى اللقطة الكاملة.

التحقق: 151 اختبار خادم (1310 تأكيدات)، 90 اختبار واجهة، وفحص شاشة النتائج على عرضي 320 و1440 بكسل. لا توجد تغييرات SQL.
